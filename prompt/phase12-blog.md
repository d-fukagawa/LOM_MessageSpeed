# Phase 12-C: 導入案内ブログ文章ドラフト作成計画

## 目的

ConfigEditor `0.3.0`による新しい導入フローを、初めてBepInEx MODを導入する利用者にも理解できるブログ記事として説明する。

READMEより背景と画面操作を丁寧に扱い、SNSより詳しい導入・更新・安全仕様・トラブル対応を提供する。一方で、READMEと異なる手順や独自の断定を作らず、正式な仕様と配布情報はREADMEへ一本化する。

Phase 12ではドラフトだけを作成し、ブログサービスへの投稿、下書き保存、画像アップロード、公開は行わない。commit、push、tag、GitHub ReleaseもPhase 13へ分離する。

## 1. 想定読者

### 主対象

- 『活俠傳』の文字送りを速くしたいWindows利用者
- MOD導入経験が少ない利用者
- 旧`LOM_MessageSpeed 0.1.0`を手動導入済みの利用者

### 前提知識

- ZIPの展開とWindows EXEの起動はできる
- Steamからゲームフォルダを開く操作は説明があればできる
- BepInEx、Plugin DLL、cfg、SHA-256は知らない可能性がある

専門用語は初出で短く説明し、内部実装の詳細は必要な場合だけ補足へ分離する。

## 2. 記事の役割

記事で達成すること:

- 新しいツールで何が簡単になったか理解できる
- 必要なファイルと前提を判断できる
- 初回導入を完了できる
- 文字送り倍率を変更してゲームを起動できる
- `0.1.0`から安全に更新できる
- 自動導入できない場合に無理な上書きをしない
- 問題報告に必要な情報を集められる

記事で行わないこと:

- BepInExバイナリの再配布
- セキュリティ警告を無条件で回避させる案内
- 未知DLLの強制削除
- 実験版Motion / Transitionの利用案内
- 動作や安全性の絶対保証

## 3. 推奨記事構成

### 3.1 導入

- 旧フローではPlugin ZIPと設定エディタを別々に扱う必要があった
- `0.3.0`では一つの設定ツールからPlugin導入、設定保存、ゲーム起動まで行える
- オンライン取得ではなく、承認済みDLLをEXEへ内蔵している

「以前が危険だった」と誤解させる比較は避け、操作数が減ったことを中心に説明する。

### 3.2 このツールでできること

- ゲームフォルダの確認
- BepInEx導入状態の確認
- 文字送りPluginの新規導入
- 確認済み`0.1.0`からの更新
- `Enabled`と`SpeedMultiplier`の編集
- ゲーム起動

対象外:

- BepInEx本体の自動ダウンロード・展開・更新
- 自動更新やオンライン取得
- 立ち絵Motion / Transition
- 他MODの管理

### 3.3 必要環境

- Windows x64
- Steam版『活俠傳』
- BepInEx 6 Unity Mono版
- ConfigTool ZIP
- .NET Runtimeは別途不要

対応確認済みgame / Unity / BepInEx versionはPhase 13で最終確認して差し込む。

### 3.4 ダウンロード

Phase 13用プレースホルダー:

```text
{{RELEASE_URL}}
{{CONFIG_TOOL_FILE_NAME}}
{{CONFIG_TOOL_ZIP_SHA256}}
{{CONFIG_EDITOR_EXE_SHA256}}
```

ZIP内がEXE、README、LICENSEの3ファイルであることを説明する。Plugin DLLが見えないのはEXEへ内蔵されているためで、欠落ではないと補足する。

### 3.5 BepInExの準備

- Unity Mono版を選ぶ理由
- ゲームルートへ展開する位置
- 一度ゲームを起動・終了して`BepInEx`フォルダを生成する流れ
- BepInEx 5やIL2CPP版は対象外
- ConfigEditorはBepInExなしでも起動でき、ゲームフォルダ確認後に導入サポートと再確認を利用できる
- 初心者向け本文では「名前に`Unity.Mono-win-x64`と書かれたZIPを選ぶ」と直接案内し、MonoとIL2CPPの技術差は補足へ分離する
- BepInEx 6の別buildは互換性の注意、確認済みbe.692のSHA-256不一致は完全性の問題として区別する
- 問題時は、backupとrollbackを含む作者管理の再導入Gist `https://gist.github.com/d-fukagawa/7557dd9f2128d2ac59fec677a31541f1`へ案内する

公式BepInEx URLは公開前に再確認する。記事内へ第三者ファイルの直リンクを固定する場合は、公式配布元だけを使用する。

### 3.6 初回インストール

画面の順序どおりに説明する。

1. ゲームを完全終了
2. ZIPを展開してEXEを起動
3. 自動検出または手動指定
4. `Mortal.exe`を確認し、導入サポートからBepInExを手動導入
5. 初回起動後にBepInEx状態を再確認
6. 「プラグインをインストール」
7. 確認ダイアログのgame root、導入先、version、SHA-256を確認
7. 完了後に「確認済み」と表示されることを確認

導入先をコードブロックで示す。

```text
<GameRoot>\BepInEx\plugins\LOM_MessageSpeed\LOM_MessageSpeed.dll
```

### 3.7 文字送り設定

設定画面とcfgの対応を説明する。

```ini
[General]
Enabled = true

[Message]
SpeedMultiplier = 1.5
```

`1.0`、`1.5`、`2.0`、`0.5`の例と、範囲`0.1`～`10.0`を記載する。句読点待機、入力待機、演出等は倍率対象ではないことも説明する。

### 3.8 ゲーム起動と反映確認

- 保存後に「ゲームを起動」
- ゲーム起動中は保存・Plugin導入不可
- 反映されない場合はゲームを完全終了して再保存
- `1.0`と`2.0`で通常会話を比較する確認例

### 3.9 `0.1.0`からの更新

- ツールが確認済み旧版hashを検出した場合だけ更新ボタンを表示
- cfgは保持
- 旧DLLは`.bak`へ1世代保存
- 同一承認版なら更新日時も変更しない
- 実験版や由来不明DLLは自動上書きしない

### 3.10 なぜ自動上書きしない場合があるか

hashを「ファイル内容を識別する値」と平易に説明する。

同じversion表示でも内容が異なる可能性があるため、確認済みファイル以外を自動上書きしない。これは故障ではなく、利用者のファイルを保護する安全動作であることを伝える。

### 3.11 トラブルシューティング

最低限、次の見出しを設ける。

- ゲームフォルダが見つからない
- BepInExが見つからない
- インストールボタンが表示されない
- 「自動導入できません」と表示される
- 重複配置と表示される
- ゲーム起動中または判定不能になる
- 書込権限がない
- SmartScreen等の警告
- 設定が反映されない
- 元へ戻したい

解決策は破壊的でない順に案内する。

1. ゲーム終了
2. path、version、hash、BepInEx状態確認
3. DLLとcfgのバックアップ
4. READMEとIssue確認
5. 必要な場合だけ手動整理

### 3.12 アンインストール

- ゲームを終了
- 対象Plugin DLLだけを削除
- cfgが残ってもゲームへ影響しない
- ConfigToolは展開先から削除可能
- BepInExやゲーム本体、セーブデータを変更する必要はない

### 3.13 安全仕様

利用者向け要約:

- オフライン
- 管理者権限への自動昇格なし
- 未知DLLを上書きしない
- ゲーム起動中は変更しない
- cfg、ゲーム本体、BepInEx、他MODを変更しない
- 更新前DLLを1世代backup
- 導入後に内容を再確認し、失敗時は復元を試みる

内部実装の詳細は折りたたみ相当の補足節へ置く。

### 3.14 既知制限と問題報告

- 非公式、`1.0`未満
- 将来のゲーム・BepInEx更新は未保証
- clean Windows確認結果をPhase 13で記載
- すべての会話、MOD組み合わせ、権限・filesystem構成を網羅していない
- Issueへ添える情報
- ログやpathの個人情報確認

## 4. 画像計画

ブログで画像を使用する場合の候補:

1. ConfigTool ZIP内容
2. ゲームフォルダ確認済み画面
3. 未導入状態のPlugin欄
4. インストール確認ダイアログ
5. インストール済み状態
6. 文字送り倍率設定
7. 自動導入を拒否した状態の例

画像作成・撮影は別作業とし、Phase 12-Cでは挿入位置とキャプションだけをドラフトへ用意してよい。

画像にはユーザー名、Steam libraryの個人path、セーブ情報、他MOD一覧、ログ内個人情報を映さない。ぼかし前提ではなく、撮影時点で隔離test pathを使用する。

## 5. READMEとの整合

ブログ固有の説明を追加しても、次の情報源はREADMEとmanifestを正とする。

- version
- ファイル名
- SHA-256
- 対応環境
- install path
- 設定範囲
- 更新対象
- 既知制限

README変更後にブログを照合し、矛盾がある場合はブログ側を修正する。ブログからREADMEへ詳細・最新情報の確認を誘導する。

## 6. トーンと表現

- 初心者を置き去りにしない
- 一文を短めにし、操作と結果を同じ段落へ置く
- 「payload」「manifest」「PE metadata」は通常本文で使わない
- 「hash」は初出で説明する
- 不安を煽らず、安全動作の理由を具体的に説明する
- 「絶対安全」「ワンクリックですべて完了」など過剰表現を避ける
- BepInExの導入が別途必要なため「ツールだけですべて完了」とは書かない

## 8. レビュー

### 手順レビュー

- 新規の隔離環境を想定して記事だけで操作を再現
- `0.1.0`更新環境を想定して設定保持まで確認
- 自動導入拒否状態から危険な操作へ誘導していない
- アンインストールで他ファイルを削除させない

### 文書レビュー

- READMEとversion、path、設定値が一致
- 見出しから目的の情報を探せる
- 長い背景説明より先に導入手順へ到達できる
- コードブロックがコピー可能
- placeholderが明確
- 画像なしでも記事が成立する

### 公開前レビュー

- Phase 13の正式Release assetで手順を再確認
- clean Windows結果を反映
- URLとhashを再計算・照合
- screenshotの個人情報を確認
- ブログ側previewでPC・スマートフォン表示確認
