# Phase 12-B: 導入案内・更新内容案内（SNS用）作成計画

## 目的

ConfigEditor `0.3.0`と文字送り専用Plugin `0.2.0`について、SNSで短時間に理解できる導入案内と更新内容案内を作成する。

新規利用者には「何をダウンロードし、どのボタンを押すか」、既存`0.1.0`利用者には「何が変わり、設定が維持されるか」を伝える。技術的な安全仕様は、安心材料になる範囲へ短く要約する。

投稿や予約投稿はPhase 12の対象外とし、Phase 13のRelease URL確定後に投稿できるドラフトを作る。

## 1. 作成する文章

最低限、次の4種類を用意する。

1. リリース告知の短文
2. 新規利用者向け導入案内
3. 既存`0.1.0`利用者向け更新案内
4. 注意事項・トラブル時案内

必要に応じて、各文章を単独投稿版とスレッド版へ分ける。

## 2. 想定媒体

媒体を特定せず利用できる共通原稿を先に作り、次の差分を用意する。

### Xなど短文媒体

- 1投稿版
- 3～5投稿のスレッド版
- URL、ハッシュタグ、画像添付を考慮した文字数
- 冒頭2行だけで要点が伝わる構成

### Bluesky等

- 外部リンク込みでも読みやすい短文
- 過剰なハッシュタグを避ける

### Discord等

- 箇条書きとコード表記を使える少し詳しい版
- 更新対象、導入手順、注意事項を一つの投稿へ集約

実際に使用する媒体と文字数上限が未確定の場合は、共通短文版、スレッド版、長文版の3段階で作る。

## 3. 固定するメッセージ

### 最重要メッセージ

```text
設定ツールだけで、文字送りMOD本体の導入・更新・設定・ゲーム起動まで行えるようになりました。
```

### 必須情報

- 非公式MOD / 非公式ツール
- 対象ゲーム: 『活俠傳（Legend of Mortal）』
- ConfigEditor `0.3.0`
- 内蔵Plugin `0.2.0`
- Windows x64
- .NET Runtimeの別途導入不要
- ConfigEditorはBepInExなしでも起動可能
- ゲームフォルダ確認後、名前に`Unity.Mono-win-x64`と書かれたBepInEx ZIPを手動導入
- BepInExが正常に動作しない場合の再導入手順: `https://gist.github.com/d-fukagawa/7557dd9f2128d2ac59fec677a31541f1`
- オフライン動作
- 文字送り機能だけが対象
- 立ち絵Motion / Transitionは含まない

### 安全仕様として伝える内容

- `0.1.0`から設定を維持して更新可能
- 未知DLLや新しい版は自動上書きしない
- cfg、ゲーム本体、BepInEx、他MODは変更しない
- ゲーム起動中は導入・保存しない

内部用語のmanifest、payload、atomic replace、reparse pointは原則として投稿本文へ出さない。詳しい安全仕様はREADMEへ誘導する。

## 4. リリース告知短文

構成:

1. 更新を一文で告知
2. 何が簡単になったか
3. 必要な前提
4. Download / READMEリンク
5. 非公式であること

ドラフトでは次のプレースホルダーを使用する。

```text
{{RELEASE_URL}}
{{README_URL}}
{{CONFIG_TOOL_ZIP_SHA256}}
{{VERSION}}
```

Phase 13前に架空URLを埋めない。

## 5. 新規導入案内

SNS本文では手順を5段階以内へ圧縮する。

1. ConfigTool ZIPを展開してEXE起動
2. ゲームフォルダを確認
3. 導入サポートで`Unity.Mono-win-x64`と書かれたZIPを選び、手動導入・再確認
4. 「プラグインをインストール」
5. 倍率を保存して「ゲームを起動」

補足リンク先のREADMEには詳細手順とSHA-256確認方法があることを案内する。

## 6. 既存利用者向け更新案内

次を明記する。

- 確認済み`0.1.0`は「プラグインを更新」から`0.2.0`へ更新可能
- `lom-messagespeed.cfg`は維持
- 更新前DLLは`.bak`へ1世代保存
- `Enabled`と`SpeedMultiplier`の使い方は同じ
- 立ち絵実験機能は正式版へ含めない

過去の実験版利用者に対しては、自動上書きされないこととREADME確認を案内し、手動削除を短文だけで安易に促さない。

## 7. 注意事項投稿

想定する問い合わせを先回りする。

- ボタンが「自動導入できません」になる
- BepInExが見つからない
- ゲーム起動中と表示される
- SmartScreenが表示される
- 設定が反映されない

回答の基本形:

```text
ゲームを完全に終了し、表示されたパスとREADMEのSHA-256を確認してください。
確認済みではないDLLは安全のため自動上書きしません。
```

セキュリティ警告の無効化や未知DLLの強制削除を促さない。

## 8. トーン

- 親しみやすいが、公式サポートと誤認させない
- 「絶対安全」「完全対応」「すべての環境で動作」など断定を避ける
- 技術説明より利用者の操作と結果を優先
- 問題報告を歓迎しつつ、ログの個人情報確認を案内
- 絵文字やハッシュタグは媒体ごとに控えめにする

## 9. Phase 13で差し込む情報

- 正式versionとRelease名
- GitHub Release URL
- README URL
- ConfigTool ZIP SHA-256
- EXE SHA-256
- 対応確認済みゲームversion
- clean Windows確認結果
- 公開日時
- BepInEx再導入Gist URL

RC2のhashやローカルpathを投稿ドラフトへ固定しない。

## 10. レビュー

### 正確性

- ConfigToolだけでPluginを導入できると伝わる
- BepInExは別途必要と伝わる
- .NET Runtime不要と伝わる
- `0.1.0`更新でcfgが維持される
- 未知版を自動上書きしない
- 文字送り以外の機能を宣伝していない

### 読みやすさ

- 最初の2行で更新の価値が分かる
- 手順が長すぎない
- URLがなくてもドラフトとして意味が通る
- 新規利用者向けと既存利用者向けが混同されない
- 注意事項だけが過度に目立たない

### 公開前確認

- placeholderがすべて置換されている
- URLが公開済みReleaseを指す
- version、ファイル名、hashがRelease assetと一致
- 誤字、文字数、改行、リンクカード表示を確認

## 12. 完了条件

- 新規導入、既存更新、注意事項の各ドラフトがある
- 短文、スレッド、長文の用途別原稿がある
- 新導入フローとBepInEx前提が正確
- cfg維持と未知版非上書きを簡潔に説明している
- Phase 13でURL、hash、clean Windows結果を差し込める
- 投稿、予約投稿、外部送信を行っていない
- commit、push、tag、Releaseを行っていない
